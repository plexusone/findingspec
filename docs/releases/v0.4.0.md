# v0.4.0 Release Notes

**Release Date:** November 18, 2026

## Highlights

- **Findings from several producers**: `findingspec.Merge` combines the sets several tools write about the same work,
  and `content.FindingID` builds IDs that are stable across runs and never collide between producers.
- **Review rules for claims**: six content rules for problems people find when they review claims and their citations.

## Merging Findings

```go
all, err := findingspec.Merge(static, notes, audio)
```

`Merge` keeps the findings in order and fails with `ErrDuplicateID`, naming each repeated ID, when two findings share
one. Nil sets are skipped. Let each producer write its own set, so they run independently without overwriting each
other.

## Finding IDs

```go
content.FindingID("CF", "claim-founding", content.RuleLessPrecise) // "CF-claim-founding-lessPrecise"
```

The ID is the producer's prefix, the subject (a claim ID, or a narration segment ID) and the rule's last segment. A
finding raised again gets the same ID, so a decision about it stays attached from one review round to the next.

## Review Rules

| Rule | Problem |
|------|---------|
| `content.claim.lessPrecise` | The claim is accurate but leaves out a full name, date or figure its sources give |
| `content.claim.subjectMissing` | The claim, or its supporting quotation, does not name who or what it is about |
| `content.evidence.duplicate` | A quotation repeats, or is contained in, another the claim cites from the same source |
| `content.evidence.offClaim` | A supporting quotation bears on no part of the claim |
| `content.evidence.stance` | A citation's stance, such as disputes, is not what its passage shows |
| `content.review.note` | A person's note on the claim that no other rule describes |

## Compatibility

Additive. Existing rules, types and finding projections are unchanged.
