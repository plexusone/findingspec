## [v0.2.0] - 2026-11-15

### Highlights

- A `content` domain for the accuracy and attribution of published content: a claim its cited source does not support, a quotation not found in its source, a citation to an unreliable source. Claim checkers raise these findings and carry them through review with the shared status lifecycle
- Security findings can now carry root cause, product impact, exploit notes, verification, typed relationships to work items and fixes, and a disclosure lifecycle, so one record spans discovery, engineering fix, and product impact
- Findings render into a formal report that pandoc converts to DOCX or PDF, with a shareable audience that keeps exploit detail out

### Added

- `findingspec`: typed `Relationship` links (threat, control, requirement, tracking item, fix, test, duplicate) and `Verification` on `Finding` ([`884978a`](https://github.com/plexusone/findingspec/commit/884978a))
- `security`: `RootCause`, `Impact`, `Exploit`, and `Publication` (visibility, disclosure state, GHSA/CVE/OSV/Go vulnerability IDs, affected version ranges) on `Vulnerability` and its `Detail` ([`69339fe`](https://github.com/plexusone/findingspec/commit/69339fe))
- `security`: `Exception.Rationale`, the approver's stated justification for accepting a risk, so an accepted vulnerability can be reported with its reason ([`0c3cff0`](https://github.com/plexusone/findingspec/commit/0c3cff0))
- `report`: render a `FindingSet` as a formal, pandoc-ready Markdown report (metadata block, executive summary, severity tables, linked findings overview, per-finding detail) for a shareable or internal audience; the shareable default omits exploit detail, evidence payloads, and code snippets ([`f5d9840`](https://github.com/plexusone/findingspec/commit/f5d9840))
- `findingspec`: `DomainContent`, for findings about claims and their sources ([`b6b825b`](https://github.com/plexusone/findingspec/commit/b6b825b))
- `content`: `Issue`, a problem with one claim or one of its sources, projected by `ToFinding` with the claim as the location (`Location.Component` the claim ID, `File` the document, `Snippet` the statement) and `claim:`/`source:` tags; `ClaimID` reads the claim back from a finding ([`b6b825b`](https://github.com/plexusone/findingspec/commit/b6b825b))
- `content`: twelve common rule IDs, from `content.evidence.none` and `content.quote.notFound` to `content.facts.missing` and `content.claim.singleSource` ([`b6b825b`](https://github.com/plexusone/findingspec/commit/b6b825b))

### Documentation

- Analysis, verification, and disclosure fields on security findings ([`e5061ed`](https://github.com/plexusone/findingspec/commit/e5061ed))
- Exception rationale in the security domain guide ([`45794ee`](https://github.com/plexusone/findingspec/commit/45794ee))
- Report reference page, README section, and navigation; report rendering in the PRD, TRD, and roadmap ([`3dfa3a0`](https://github.com/plexusone/findingspec/commit/3dfa3a0))

## [v0.1.0] - 2026-10-04 ([`e0d5aec`](https://github.com/plexusone/findingspec/commit/e0d5aec))

### Highlights

- Initial release — a domain-neutral model that normalizes findings across security, accessibility (a11y), internationalization (i18n), and quality engineering (qe) into one canonical `Finding` with a typed, per-type `Detail` subsection
- Two-level `Domain` + `Type` taxonomy with ingest adapters for open-source scanners: gitleaks, axe-core, and govulncheck in-repo (Grype, Trivy, and AWS Inspector via their tool libraries)
- Call-graph reachability (via govulncheck) as a first-class prioritization signal, and a canonical container/SCA package-vulnerability shape shared by Grype, Trivy, and Inspector

### Added

- `findingspec`: canonical `Finding` and `FindingSet` with domain/severity/open filtering, counting, severity ordering, and a `Summary` analytics rollup ([`62ea7a4`](https://github.com/plexusone/findingspec/commit/62ea7a4))
- `findingspec`: shared vocabulary — `Severity` (via the priority-frameworks Severity framework), `Status`, `Confidence`, `Domain`, `Source`, `Location` (code, runtime, or RFC 6901 JSON Pointer), `Evidence`, `Remediation`, `Reference` ([`62ea7a4`](https://github.com/plexusone/findingspec/commit/62ea7a4))
- `findingspec`: typed per-type `Detail` subsection — `Finding.Type`, `SetDetail`, and generic `DetailAs[T]` ([`62ea7a4`](https://github.com/plexusone/findingspec/commit/62ea7a4))
- `security`: `Vulnerability` with inherent vs. residual severity, compensating controls, and exception-driven effective severity; `Secret`; `CVSS`; `Package`/`Fix`/`Artifact` for SCA and container scans; and call-graph `Reachability` ([`a15f74d`](https://github.com/plexusone/findingspec/commit/a15f74d))
- `a11y`: WCAG `Issue` with conformance level and impact-to-severity mapping ([`424f48f`](https://github.com/plexusone/findingspec/commit/424f48f))
- `i18n`: internationalization/localization `Issue` types ([`6665a54`](https://github.com/plexusone/findingspec/commit/6665a54))
- `qe`: quality-engineering `Failure` for end-to-end and user-journey findings ([`fcf2126`](https://github.com/plexusone/findingspec/commit/fcf2126))
- `adapters/gitleaks`: secret-scan JSON report to security/secret findings, with redaction and provider/kind inference ([`45a1133`](https://github.com/plexusone/findingspec/commit/45a1133))
- `adapters/axe`: axe-core results JSON to a11y/wcag findings, one per element, with WCAG criterion/level parsed from tags ([`475e6ca`](https://github.com/plexusone/findingspec/commit/475e6ca))
- `adapters/govulncheck`: `govulncheck -json` to security/sca findings, deriving call-graph reachability (state, vulnerable symbol, example call paths) ([`8f2d0b6`](https://github.com/plexusone/findingspec/commit/8f2d0b6))
